## 三、结构性发现（比来源数量更重要）

实测暴露出三个**设计层面的问题**，都会影响方案选择。

### 发现 1：抓取必须在海外服务器上跑

以下来源在你当前网络下 **TCP 连接被直接阻断**（能解析出地址，但 443 端口无响应，是典型的地区网络限制特征）：

Hugging Face（博客 + Daily Papers）、Google Research、Meta AI、Mistral AI、xAI

**也就是说：抓取程序必须运行在美国的服务器上**，不能在你电脑上跑。原设计用的是 GitHub Actions（美国机器）执行抓取，**这条反而印证了原方案是对的**。

> 这 6 个源是否真的在海外服务器上可用，要等流水线跑起来才能确认。我标注为“预计可用”，不做没有依据的保证。

### 发现 2：托管的网站，国内可能打不开

原设计选的 **GitHub Pages（github.io 域名）在你当前网络下打不开**。实测各免费托管平台：

| 平台域名 | 国内实测 | 结论 |
|---|---|---|
| github.io（GitHub Pages） | ❌ 超时 | 不能用 |
| workers.dev（Cloudflare Workers） | ❌ 超时 | 不能用 |
| vercel.app（Vercel） | ❌ 超时 | 不能用 |
| **pages.dev（Cloudflare Pages）** | ✅ 正常 | **可用** |
| **netlify.app（Netlify）** | ✅ 正常 | **可用** |

**结论：托管要从 GitHub Pages 换成 Cloudflare Pages 或 Netlify。**

好消息：Cloudflare Pages 免费支持私有仓库（代码不必公开），而且支持用命令行直接部署，**顺带绕开了 git 权限那个问题**。

### 发现 3：有些源你自己点开也可能打不开

这条属于产品层面的问题，比较关键：

信息流里会出现 Hugging Face、Google DeepMind、Meta AI、Mistral、xAI 的条目。**这些网站在国内被屏蔽——你在信息流里能看见标题，但点进去可能打不开。**

可选处理方式：

1. **照常收录**：读到标题就够了，打不开的跳过
2. **点击时提示**：点这类来源时先提示“该站点可能需要代理访问”
3. **换掉这些源**：只保留国内能打开的，代价是信息覆盖变窄
4. **加镜像阅读按钮**：先不做，列入未来增强

## 四、三个不可用来源的处理建议

| 来源 | 问题 | 建议 |
|---|---|---|
| 机器之心 | 官网已改为“数据服务”落地页，/rss 返回的不是订阅源 | **移除**；以后恢复公开源可随时加回 |
| 新智元 | 域名 ai-era.cn 无法解析 | **移除**，或由你提供正确的网站地址 |
| 字节 Seed | 页面由脚本动态加载，静态抓取取不到 | 尝试找接口；找不到就移除 |

## 五、环境问题记录（只影响我的操作，不影响成品）

当前运行环境里 **PowerShell 和 curl 的 HTTPS 请求是坏的**（Windows 凭据库报错 SEC_E_NO_CREDENTIALS），所有网络请求必须用 Python 的 requests 走。

- 后续所有联网验证脚本，我都用 Python 写
- 只影响开发环境，对最终跑在海外服务器上的程序没有影响
