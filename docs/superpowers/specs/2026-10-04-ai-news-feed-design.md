# AI 每日前沿 — 设计文档

- 日期：2026-10-04
- 状态：待评审
- 作者：用户 + Codex

---

## 1. 背景与目标

用户希望每天不用自己四处翻网站，就能看到**全球 AI 领域最新的新闻、资料与创新动态**。

核心目标：把分散在各个 AI 公司、实验室、论文平台和中文媒体上的最新内容，聚合成**一个持续滚动、按时间倒序的信息流页面**，每条都能一键跳转到原始网站。

### 1.1 使用者

- 只有用户本人使用。单用户、无需登录、无社交功能。
- 使用设备：一台 Windows 电脑 + 一部手机 + 一台平板。

### 1.2 成功标准

1. 打开页面，能在一个滚动列表里连续看到近期的 AI 动态，由新到旧排列。
2. 每条信息都能点击跳到原文所在网站或平台。
3. 每天自动更新 3 次，且支持用户手动触发一次即时更新。
4. 手机、平板、电脑三种设备都能正常打开与阅读。
5. 运行成本为 0 元，不需要自己维护服务器。

### 1.3 明确不做（非目标）

- 不做 AI 摘要、不做翻译。用户可直接阅读英文原文。
- 不做用户账号、登录、评论、分享等社交功能。
- 不做推送通知（列为未来可选增强）。
- 不做全文抓取与离线存档，只聚合标题、来源、时间与原文链接。

## 2. 内容来源

来源覆盖三类：全球顶尖 AI 公司/实验室的一手动态、学术论文、中文权威 AI 媒体。

### 2.1 A 类：AI 公司 / 实验室官方源（category = `lab`）

> **实际采用的来源以 `sources.yaml` 为准**（2026-10-04 实测后确定，共 30 个来源、启用 26 个）。
> 逐源实测结果见 `docs/source-availability-2026-10-04.md`。本节以下表格是当初的候选范围，其中部分来源经实测已停用。

| 分组 | 来源 |
|---|---|
| 美国大厂 | OpenAI、Anthropic、Google DeepMind、Google Research、Meta AI、Microsoft Research、NVIDIA AI、Apple ML Research、Amazon AWS ML、IBM Research |
| 新兴公司 | Mistral AI、xAI、Cohere、Stability AI |
| 开源生态 | Hugging Face（博客 + Daily Papers） |
| 中国大厂 / 新锐 | DeepSeek 深度求索、阿里通义、字节 Seed、月之暗面、智谱 AI、MiniMax |

### 2.2 B 类：学术论文（category = `paper`）

- arXiv：`cs.AI`、`cs.LG`、`cs.CL` 三个方向的最新论文
- Hugging Face Daily Papers
- 上述各实验室官方博客中发布的论文（随 A 类一并抓取）

### 2.3 C 类：中文权威 AI 媒体（category = `cn-media`）

- 机器之心
- 量子位
- 新智元
- 智东西
- 雷锋网（AI 科技评论）

### 2.4 来源可用性约定

每个来源按下列优先级适配，取第一个可用者：

1. **RSS / Atom** —— 首选，最稳定
2. **官方 API / JSON** —— 次选
3. **网页 HTML 解析** —— 兜底（部分中文媒体无现成 feed）

**约束与风险**：少部分中文媒体主要发布在微信公众号，可能不存在稳定接口。实现阶段逐个验证；**无法稳定获取的来源会被明确记录并移除或替换，不允许留下长期失效的源**。最终以实际验证通过的源清单为准。

## 3. 功能需求

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 信息流列表 | 竖向滚动，按发布时间由新到旧排列，每条显示来源、相对时间、原文标题、跳转链接 |
| F2 | 跳转原文 | 点击条目在新标签页打开原始页面，不打断当前浏览 |
| F3 | 分类筛选 | 顶部标签切换：全部 / 实验室 / 论文 / 中文媒体 |
| F4 | 关键词搜索 | 输入关键词，实时过滤标题与来源名 |
| F5 | 已读标记 | 点击过的条目自动变淡，状态存于浏览器本地 |
| F6 | 收藏 / 稍后读 | 手动收藏条目，并提供"只看收藏"筛选 |
| F7 | 主题切换 | 跟随系统深色/浅色，支持手动切换并记住选择 |
| F8 | 响应式布局 | 手机单列、平板与电脑更宽版式，一套页面自适应 |
| F9 | 更新时间显示 | 页面顶部显示真实的最近更新时间与条目数量 |
| F10 | 降级提示 | 部分来源抓取失败时，页面角落提示来源不可用，但列表照常展示 |
| F11 | 手动更新 | 用户可手动触发一次即时抓取，不必等到下一个定时点 |
| F12 | 自动清理已读记录 | 页面加载时清除已不在列表中的已读标记；收藏不受影响 |
| F13 | 手动清理 | 设置区提供"清空已读""清空收藏"按钮 |
| F14 | 数据新鲜度保障 | 读取数据文件时附带版本参数，避免浏览器或平台缓存导致显示旧内容 |

### 3.1 关于 F11 手动更新的实现约束

页面是纯静态站点，没有后端，因此**无法在页面内安全地直接调用抓取任务**（把访问令牌写进公开页面等于泄露）。

采用的方案：手动更新按钮在新标签页打开托管平台的"运行工作流"页面，用户在那里点击一次 Run workflow 触发。代价是多一次点击，收益是**零密钥泄露风险、零额外成本**。

若未来愿意增加一个轻量中转服务，可升级为真正的"一键触发"。本期不做。

## 4. 页面设计

单页信息流，结构如下：

```
┌────────────────────────────────────────────┐
│  AI 每日前沿        ● 更新于 14:00  ⟳ 手动更新 │
│  [全部] [实验室] [论文] [中文媒体] [收藏]  🔍  │
├────────────────────────────────────────────┤
│  OpenAI                          · 2 小时前 │
│  Introducing GPT-5.5 …                   ↗ │
├────────────────────────────────────────────┤
│  机器之心                        · 3 小时前 │
│  某篇中文报道标题……                       ↗ │
├────────────────────────────────────────────┤
│  arXiv · cs.LG                   · 5 小时前 │
│  Paper title goes here ...               ↗ │
└────────────────────────────────────────────┘
```

- 每条信息：来源标签 · 相对时间 · 原文标题 · 跳转图标 `↗`
- 时间同时提供绝对时间（悬停显示）
- 已读条目降低对比度，收藏条目高亮标记
- 空状态、加载状态、来源不完整状态均有明确提示
- 键盘可达：条目可 Tab 聚焦、回车打开
- 设置区提供"清空已读""清空收藏"两个按钮

### 4.1 界面语言

界面文案使用中文；内容标题保留原文语言，不翻译。

## 5. 系统架构

三个组成部分，通过"定时任务 → 数据文件 → 静态页面"接力，无服务器、无数据库。

```
① 抓取器（定时任务，每天 3 次）
       │  从各来源抓取最新内容
       ▼
② 整理器
       │  统一字段 → 合并上一版 → 去重 → 按时间倒序
       │  截取最近 7 天、最多 500 条
       ▼
   feed.json（数据文件）
       ▼
③ 静态网页
       │  读取 feed.json 渲染信息流
       │  筛选 / 搜索 / 已读 / 收藏 全部在浏览器本地完成
       ▼
   免费静态托管 → 电脑 / 手机 / 平板打开
```

### 5.1 技术选型

| 组成 | 选型 | 理由 |
|---|---|---|
| 抓取与整理 | Python 3.11+（`feedparser`、`httpx`、`beautifulsoup4`、`PyYAML`） | 解析 RSS / HTML 生态成熟，脚本级任务足够 |
| 前端 | 原生 HTML + CSS + JavaScript | 无构建步骤，静态托管可直接部署，长期免维护 |
| 定时执行 | GitHub Actions 定时任务（cron，按 UTC 配置） | 免费、免运维，与托管同一平台 |
| 托管 | **GitHub Pages** | 零成本、三种设备均可访问；与定时任务同平台，只需一个账号。实测 `github.io` 在用户网络下需开启加速器，用户已具备（详见 13 节） |
| 存储 | `feed.json` 数据文件 | 数据量小，无需数据库 |

### 5.2 目录结构（规划）

```
.
├── docs/superpowers/specs/        # 设计文档
├── src/
│   ├── collectors/                # 每个来源的抓取适配器
│   ├── normalize.py               # 字段统一
│   ├── dedupe.py                  # 去重
│   └── build_feed.py              # 主流程，产出 feed.json
├── web/                           # 静态前端（index.html / style.css / app.js）
├── data/feed.json                 # 生成的数据文件
├── sources.yaml                   # 来源清单配置
├── tests/                         # 自动化测试
└── .github/workflows/update.yml   # 定时任务定义
```

## 6. 数据模型

`feed.json` 结构：

```json
{
  "generated_at": "2026-10-04T20:00:12+08:00",
  "window_days": 7,
  "item_count": 342,
  "sources_ok": 24,
  "sources_failed": ["量子位"],
  "items": [
    {
      "id": "sha1:9f2c…",
      "title": "Introducing GPT-5.5",
      "url": "https://openai.com/index/…",
      "source": "OpenAI",
      "source_id": "openai",
      "category": "lab",
      "lang": "en",
      "published_at": "2026-10-04T09:12:00Z",
      "fetched_at": "2026-10-04T20:00:01+08:00"
    }
  ]
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `id` | 稳定标识，由规范化后的 URL 生成（`sha1` 前缀），供已读/收藏状态引用 |
| `category` | `lab` / `paper` / `cn-media` |
| `lang` | `en` / `zh`，仅作标注，不做翻译 |
| `published_at` | 来源给出的发布时间（UTC）；缺失时用抓取时间兜底 |
| `generated_at` | 本次抓取的真实完成时间，用于页面顶部展示 |
| `sources_ok` / `sources_failed` | 用于页面降级提示 |

`sources.yaml` 结构（每个来源一条）：

```yaml
- id: openai
  name: OpenAI
  category: lab
  lang: en
  type: rss
  url: https://openai.com/news/rss.xml
  homepage: https://openai.com/news/
```

## 7. 数据流

1. 定时任务启动（或用户手动触发）。
2. 读取 `sources.yaml`，并发抓取各来源，设置超时与有限重试。
3. 每个来源经适配器解析为标准条目，记录成功/失败。
4. 从**当前已发布站点**下载上一版 `feed.json` 作为历史基线（详见第 8.1 节）。
5. 合并新旧条目 → 按规范化 URL 去重 → 按 `published_at` 倒序。
6. 截取最近 7 天、最多 500 条，写出新的 `feed.json`。
7. 将静态页面与数据一起发布到托管平台。
8. 用户设备打开页面，浏览器携带版本参数读取 `feed.json` 渲染信息流（避免缓存旧数据）。

## 8. 更新机制

### 8.1 为什么需要"合并上一版"

各来源的 feed 通常只保留最近若干条。为降低"两次抓取之间有条目被挤出列表而丢失"的风险，每次生成时会把**已发布的上一版数据**一并读入参与合并与去重。这样即使某个来源临时抽风，历史条目也不会凭空消失。

### 8.2 时间计划

- 频率：**每天 3 次**
- 时间点（北京时间）：**08:00 / 13:00 / 20:00**
- 实现方式：托管平台 cron 以 UTC 配置，对应 **00:00 / 05:00 / 12:00 UTC**（中国无夏令时，全年固定）
- 手动触发：额外启用 `workflow_dispatch`，供 F11 使用

### 8.3 已知偏差

免费托管平台的定时任务在整点高峰可能排队，实际执行时间可能延后数分钟至十几分钟。因此：

- 页面顶部展示的是**真实完成时间**，不做美化。
- 该延迟属平台特性，不视为故障。

### 8.4 数据保留

滚动保留最近 **7 天**、最多 **500 条**。超出部分自动淘汰。

### 8.5 本地数据（浏览器）的清理

已读与收藏状态保存在浏览器 `localStorage`，只增不减会逐渐占满存储空间（估算约一年可累积数万条，接近浏览器约 5MB 的站点配额上限，可能导致状态丢失）。

处理方式：

- **自动清理**：页面每次加载时，清除已不在当前 `feed.json` 中的已读记录。这些条目本身已超出 7 天窗口，清理不影响使用，用户无感知。
- **收藏除外**：收藏条目**永不自动清理**，由用户自行决定何时删除。
- **手动兜底**：设置区提供"清空已读""清空收藏"按钮。
- **不需要定时任务**：清理随页面加载发生，不占用任何后台资源。

> 说明：服务端数据（`feed.json`）的清理已由第 8.4 节的滚动窗口覆盖，不需要额外机制。

## 9. 错误处理与可靠性

| 场景 | 处理方式 |
|---|---|
| 单个来源超时 / 报错 | 隔离处理，仅该来源失败，其余正常产出；来源名记入 `sources_failed` |
| 解析规则因对方改版失效 | 该来源当次标记失败；页面提示；事后据此修复规则 |
| 整体任务失败 | **不覆盖已经发布的数据**，用户继续看到上一版内容 |
| 本次抓取条目为 0 | 视为异常，保留上一版，不发布空页面 |
| 网络瞬时抖动 | 设置请求超时 + 有限次重试（例如 2 次） |
| 重复条目 | 按规范化 URL 生成稳定 `id` 去重；同一来源内按 `id` 覆盖更新 |
| 来源未提供发布时间 | 使用抓取时间兜底，并在文档中记录该来源的时间不可靠 |

## 10. 安全与隐私

- 单用户、无登录，**不收集任何用户数据**。
- 已读、收藏、主题偏好仅存于浏览器 `localStorage`，不上传、不跨设备同步。已读记录随页面加载自动清理过期项，收藏永久保留（详见 8.5 节）。
- 不使用任何需要付费密钥的第三方服务。
- **不在代码或配置中存放任何访问令牌**；F11 采用"跳转到平台页面手动运行"的方式规避密钥问题。
- 使用 GitHub Pages 免费额度要求**代码仓库为公开仓库**。仓库内不含任何密钥或个人数据，公开无风险。若不愿公开，可改用 Cloudflare Pages（免费支持私有仓库），方案其余部分不变。
- 发布的是聚合后的标题与链接，不转载全文，指向原始来源。

## 12. 验收标准

1. 页面在电脑、手机、平板三种设备上均能正常打开并滚动浏览。
2. 列表按时间倒序，每条可跳转到原文，链接有效。
3. 分类筛选、搜索、已读、收藏、主题切换均可用。
4. 每天按 08:00 / 13:00 / 20:00 自动更新，页面显示真实更新时间。
5. 手动触发一次即可立即产出新版本。
6. 任意单一来源失败时，页面仍能正常展示其余内容并给出提示。
7. 页面打开时自动清理过期已读记录，收藏不被清除；手动清理按钮可用。
8. 全流程零费用运行。

## 13. 风险与待确认

| 风险 | 应对 |
|---|---|
| 部分中文媒体无稳定 feed（尤其公众号） | 逐个验证，不可用即替换或移除，并在交付时说明 |
| 来源网页改版导致解析失效 | 适配器隔离 + 失败提示；后续按需修复 |
| 免费托管平台的定时任务延迟或限额调整 | 每天 3 次的用量远低于免费额度，风险很低 |
| 已读/收藏状态不同设备不通用 | 本期接受；跨设备同步列为未来增强 |
| 站点默认公开可访问 | 内容为公开新闻聚合，无隐私数据；如需私密访问再评估 |
| 抓取源在国内被墙 | 实测确认 6 个来源（Hugging Face、Google Research、Meta AI、Mistral、xAI）在国内不可达，因此抓取必须运行在海外机器（GitHub Actions）上；本设计已满足 |
| 中文媒体可用性下降 | 实测仅量子位、雷锋网、智东西可用；原计划中的机器之心与新智元已确认无法抓取，已移除 |
| 不希望代码仓库公开 | 改用 Cloudflare Pages（免费支持私有仓库），只需另注册一个账号，其余方案不变 |

## 13.1 实测后补充的实现约定

实施过程中发现并已落地的处理规则：

| 约定 | 原因与做法 |
|---|---|
| 时间兜底要标记 | 部分来源（如 Cohere、IBM Research）列表页不提供发布时间。这类条目的时间用抓取时间兜底，并标记 `date_estimated: true`；页面显示为"时间未知"，且排序时排在真实时间的条目之后，避免"假最新"抢占顶部 |
| 综合来源要过滤 | 内容偏杂的来源（InfoQ 中文站、爱范儿、雷锋网、NVIDIA、AWS、IBM Research、Cohere）按统一的关键词表筛选 AI 相关内容（`sources.yaml` 里的 `filter_keywords` / `ai_keywords`） |
| 网页抓取要排噪 | HTML 收集器会排除导航页、标签页、分类页等非文章链接，以及"Read article"这类按钮文案 |
